# K3 X100：BG1/Zc224直接寻址编码优化

本次将已验证的BG1/Zc224编码候选接入源码构建：原生RVV输入展开、基础布局直接寻址、每批最多128字节的校验计算，以及完整覆盖缓冲区时省去清零。保留已有输出打包RVV和Zc384优化，不改变校验关系、输出数量或位序。

## 接入范围

在RISC-V RVV、非AVX2/AVX512布局下，`LDPCencoder()`对以下形状自动选择新路径：

```text
BG=1，Zc=224，Kb=22，K=4928，n_segments>first_seg
```

一次调用处理从`first_seg`开始的最多8个码块，与原接口的分组含义一致。其他形状、其他架构或关闭开关时，继续执行原函数中保留的路径。新头文件由现有编码器翻译单元直接包含，不需要单独增加CMake源文件或加载实验二进制。

| 文件，位于OAI的`openair1/PHY/CODING/nrLDPC_encoder/` | 作用 |
| --- | --- |
| `ldpc_encoder_optim8segmulti.c` | 目标及形状分支，保留原函数回退 |
| `ldpc_input_z224_rvv.h` | 原生RVV输入展开，MSB-first取位及码块位平面组合 |
| `ldpc_bg1_z224_direct_rvv.h` | 46行、2,109项校验操作数的直接地址表及e8m4计算 |
| `ldpc_bg1_z224_encoder_rvv.h` | 形状检查、基础布局准备、原计时边界和内部输出拼接 |

## 优化原理

### 输入展开

输入是紧凑字节。内部计算将多个码块同一位置的比特放在一个字节的不同位上。使用RVV gather、移位、取位和OR生成该表示，保持原MSB-first输入顺序。按当前X100实际VL，每轮从每个码块读取8字节，生成64个内部字节。

这里的内部字节属于计算表示，不等于新增的空口数据；输出打包会按当前码块提取相应位。

### 直接寻址

原基础布局将22列、每列224字节各复制两遍，共`22*224*2=9856`字节。旧实现再准备移位副本。对合法布局，旧偏移可直接换算为：

```text
新偏移 = 旧偏移 % 9856 + 旧偏移 // 9856
```

地址已在源码表中预先换算，运行时不反复做除法。2,109项读取范围均在9,856字节内，最大读取末端为9,852。保留基础双份列布局，取消额外移位副本复制。

辅助缓冲区由早期32份的315,392字节，经过16份中间候选的157,696字节，最终降为9,856字节。16份只是中间实验阶段；本次默认源码直接采用基础布局方案。

该等价关系依赖旧副本由基础数据复制／移位生成。不能把旧缓冲区每个字节都设为独立随机值后，要求地址映射仍然等价。

### 校验计算与清零

每行224个位置在X100上由`64+64+64+32`调整为`128+96`，使用硬件返回的实际VL推进，保留四个独立异或累加器。并未改变校验比特数量。

新输入展开完整写入4,928字节`cc`，校验核完整写入10,304字节`dd`，因此专用路径无需预先清零它们。输出仍按原接口复制4,480字节系统部分和10,304字节校验内部表示，共14,784字节；这是多码块位平面的内部母码输出，不能与速率匹配后紧凑发送比特长度混为一谈。

## 构建

先按仓库指南安装依赖，再从最新仓库准备一个不存在的新工作树：

```bash
bash scripts/prepare-oai-worktree.sh "$HOME/xsai-oai-direct"
```

按本机OAI流程配置该工作树。`OAI_BUILD`必须指向与该源码对应的已配置构建目录，编译器和编译目标需支持所选CPU的RVV指令：

```bash
cmake --build "$OAI_BUILD" --target ldpc -j2
```

确认运行程序实际加载新构建的`libldpc.so`。更新仓库或准备工作树不会自动覆盖现有生产库。本次使用现有XSAI ABI构建完整编码器翻译单元及私有完整codec，没有将其表述为全新依赖安装后的整项目构建。

## 对照开关

下面是编译期宏；改变开关后需要重新编译：

| 宏，定义为1 | 作用 |
| --- | --- |
| `XSAI_LDPC_DISABLE_RVV_BG1_Z224_DIRECT` | 仅关闭本次专用路径，回到此前已发布的Z224 64字节RVV校验＋原展开路径 |
| `XSAI_LDPC_DISABLE_RVV_BG1_Z224` | 关闭Z224新旧两个RVV路径，保留原Z224实现 |
| `XSAI_LDPC_DISABLE_RVV_BG1_Z384` | 独立关闭Z384 RVV优化 |
| `XSAI_LDPC_DISABLE_RVV_OUTPUT_PACK` | 独立关闭输出打包RVV优化 |

关闭DIRECT并不选择16份布局中间实验库。新代码保留了此前发布源码的回退，因此其他架构不会包含或调用RVV专用头文件。

## 正确性检查

任意有Python的设备可检查全部操作数、地址映射和分支：

```bash
python3 -m unittest discover -s tests -p 'test_ldpc*py' -v
```

在匹配RVV编译目标的RISC-V Linux设备上，用本机兼容的OAI Makefile构建参数进行原生对照：

```bash
python3 scripts/check-ldpc-z224-direct-rvv.py \
  --oai "$HOME/xsai-oai-direct" --build "$OAI_BUILD" --cc gcc-16 --cpu 0
```

脚本需要`ldpc.dir/flags.make`和`taskset`，不承诺Ninja构建参数提取；默认选当前允许集合中的最小CPU，也可以用`--cpu`明确选择支持相应RVV目标的核。它在临时目录编译、运行下列对照，不安装库：

- 输入展开：1,088组结构化／随机用例，码块组first=0/8、每组1—8码块，对照原位平面定义。
- 直接校验核：68组合法展开布局，对照原OAI内核的全部10,304字节结果。
- 完整专用入口：1,088组码块组，全部14,784字节与保留的标量取位＋原OAI校验核逐字节一致；检查形状条件和原阶段计时器。
- 只读输入、输出前缀保护和末端保护页检查，检测修改输入或越界读写。

这些是与参考实现等价的检查，不是独立标准向量认证。对不匹配架构的机器，脚本会明确拒绝原生执行；可以运行上面的Python检查。

## 性能记录与适用边界

历史候选于2026-10-31在X100 CPU0、2.2 GHz、MCS9、50 RB、106 RB载波、13符号、1个DMRS符号、2个CDM groups、tbslbrm=184424条件下测量。实际为BG1/Zc224、两个码块、9480 bit有效载荷及14400 bit速率匹配输出。

三种子20261022、42、0；各10次预热＋200正式TB，共600正式TB。每进程重复使用一份种子随机载荷，固定输入、热缓存稳态调用。硬件周期通过perf_event_open读取用户态cycles，未用频率换算。

| 历史候选对照 | 完整编码μs/TB | 用户态cycles/TB |
| --- | ---: | ---: |
| 16份布局候选 | 84.697 | 186700 |
| 直接寻址候选 | 38.824 | 84767 |

另一次历史原版测得171.255 μs/TB，但它不属于上表的同轮交替对照。历史阶段诊断的输入展开为1.690 μs、数据准备＋校验为15.751 μs、输出打包为2.242 μs；这些来自独立阶段测量，不能与完整benchmark总时间混加。

2026-11-01发布源码的实际重新编译、完整TB等价、性能复测、ARM语法检查及RFsim结果，见[发布集成验证](benchmarks/ldpc-bg1-z224-direct-integration-20261101.json)。完整结果与历史候选比较保存在[性能记录](benchmarks/ldpc-bg1-z224-direct-20261101.json)，不会将历史38.824冒充本轮新源码的实测值。

RFsim属于gNB/UE共享X100 CPU0—7的全链路验证，不是单核独立benchmark。其正式窗口错误计数与原生DLSCH计时单独记录，未采集RFsim硬件周期。私有库验证不自动部署至原工程。

本次不保证其他BG/Zc、平台、输入模式或缓存状态达到相同收益；其他配置的等价回归范围见集成验证记录。
